Code health: error message standard, structured logging, named constants, dead code

Four related cleanups, each with a rule that stops the problem coming
back rather than a one-off sweep.

**Standardised user-facing error messages (#1109)**

- Add `app/lib/errorMessages.ts` as the single catalogue of failure and
  validation text, and `safeErrorMessage()` to centralise extraction.
- Stop interpolating a caught error's `message` into UI strings — it
  leaked system vocabulary ("fetch failed", internal route names) and
  gave the user no next step. The error still reaches the logger with
  its stack.
- Add the `local/error-message-style` lint rule to enforce the shape.
- Document the standard in `docs/ERROR_HANDLING.md`.

**Structured logging, and no more `console` in production source (#1113)**

- Replace `console.*` across `app/`, `components/` and the API routes
  with `logger`, so output reaches Sentry instead of only the browser
  console.
- Tighten `no-console` to an error in production source, with no
  exceptions for `warn`/`error` — every such call site already had a
  logger call that also forwarded to Sentry, so the raw console call was
  a duplicate, not the only record.
- **Fix a defect:** `logger.error("…", err)` filed every error twice —
  `logger.error` forwarded the `Error` and `sendToSentry` captured it
  again, producing two Sentry events and double quota usage per fault.
- Add `__tests__/lib/logger.test.ts` and document the levels, the
  drain/batching behaviour and the exemptions in `docs/LOGGING.md`.

**Named constants instead of magic numbers (#1106)**

- Extract the literals in `app/**` into `app/lib/constants.ts`, grouped
  by domain and documented with JSDoc. Values are unchanged, including
  the load-bearing ones (the earnings seed RNG, the WAV header offsets
  from the RIFF/WAVE spec, the sRGB and WCAG constants).
- Enable `no-magic-numbers` for source, with tests excluded — a literal
  in a test is usually fixture data, and naming it would hide the value
  being asserted.

**Dead code and unused imports (#1108)**

- Clear unused imports from 161 findings to 0, and delete commented-out
  code the new `local/no-commented-out-code` rule flags.

**Tooling**

- Add `scripts/check-lint.js`, a ratcheted ESLint gate that fails only
  when a per-rule count *rises*, mirroring `scripts/check-complexity.js`.
  The codebase predates the rules by hundreds of files, so
  `--max-warnings 0` would make every PR red regardless of what it
  touched.
- Add the two local rules above, maintained in `eslint-rules/` because
  nothing installable covers them.
- `docs/ISSUES_CRITICAL_BUILD_AND_CI.md` records what this work
  deliberately did not fix — notably that eleven source files are
  syntactically corrupted, CI's "Unit tests" step is an `echo`, and the
  build has `continue-on-error: true`.

**Breaking changes:** none. No public API changed; the behavioural
changes are the corrected double-reporting and the removal of raw
console output in production.

**No new environment variables.**
